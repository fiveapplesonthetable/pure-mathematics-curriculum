\subsection{The Curry-Howard breakthrough: proofs as executable code}

In Chapter~29 (\emph{Second Pass: Definitions Under a Microscope}), we examined mathematical definitions as precise input/output contracts. We learned to ask: what preconditions must an object meet to qualify, and what guaranteed properties does that classification provide downstream?

Yet having a collection of definitions is only a starting point. Mathematics proceeds by chaining those contracts together to transform initial premises into a conclusion. We call that deductive sequence a \textbf{proof}.

For centuries, mathematicians viewed proofs primarily through the lens of rhetoric: a proof was an argument written to convince a reader. In the twentieth century, logicians discovered a fundamental structural link: \textbf{a proof corresponds to an executable program}.

In 1934, the American logician Haskell Curry noticed an unexpected correspondence: the formal deduction rules of \emph{intuitionistic logic}---a framework of logic where claiming an object exists requires providing an explicit algorithm to construct it---mirrored the type signatures of functions in \emph{combinatory logic} (a system that computes purely by combining functions without named variables). Thirty-five years later, in 1969, William Alvin Howard formalized Curry's observation into an exact mathematical dictionary: the \textbf{Curry-Howard correspondence}.

Under the Curry-Howard correspondence, logic and computation share the same structure: propositions correspond to data types, and proofs correspond to programs that construct elements of those types. Figure~30.1 summarizes the dictionary.

\subsection{The human compiler: managing cognitive stack depth}

Yet mathematical proofs differ from software in one essential respect: \textbf{a proof compiles in the mind of a human reader}.

A software compiler has no working-memory limit. A human reader can comfortably track only a few active variables and hypotheses at once. Reading a proof involves managing a mental stack: allocating variables, pushing assumptions during sub-proofs, and popping them when a case ends. If an author introduces multiple undeclared symbols or buries the main line of reasoning in casework, the reader's working memory is quickly overwhelmed. Clear proof writing requires the same discipline as clean code: explicit scope, managed variable lifetimes, and modular structure.

\subsection{Variable scope: allocation, leakage, and shadowing}

Every time you write ``Let $x \in S$ be arbitrary'' or ``Choose $k \in \Z$ such that $n = 2k$,'' you are allocating a variable name in the reader's working memory. Just like in a programming language, that variable has a \emph{lexical scope}---a boundary of text outside of which the name no longer exists.

\subsubsection{1. Dangling variables and scope leakage}
A variable cannot be referenced outside the local block in which it was introduced.
Consider a proof by cases:
\begin{quote}
\emph{Flawed reasoning}:\\
``Case 1 ($n$ is even): Then $n = 2k$.\\
Case 2 ($n$ is odd): Then $n = 2m + 1$.\\
Therefore $n(n+1) = 2k(2m+1) \dots$''
\end{quote}
The variable $k$ was defined strictly inside Case~1, and $m$ was defined strictly inside Case~2. In any single evaluation of the proof, either $n$ is even or $n$ is odd; the two branches never run at the same time. Multiplying $2k$ by $2m+1$ is an invalid scope violation: as Figure~30.3 illustrates, the author is attempting to read an out-of-scope variable from an inactive branch.

\subsubsection{2. Shadowing and premature binding}
If your theorem already contains a fixed parameter $c$, never write:
\begin{quote}
``Let $c$ be an arbitrary element of $S$.''
\end{quote}
Re-using the letter $c$ shadows the original parameter, overwriting its identity in the reader's mental register. Introduce a fresh symbol instead: ``Let $x \in S$ be arbitrary.''

\subsubsection{3. Bound versus free variables}
Notice the difference between a variable that persists across sentences and one that is purely internal to an expression. In the summation $\sum_{i=1}^n i = \frac{n(n+1)}{2}$, the upper limit $n$ is a \textbf{free variable} (it determines the value of the sum and exists before and after the calculation). The index $i$ is a \textbf{bound variable} (a dummy index local to the summation operator). Writing ``Because $i \le n$, we deduce...'' after the sum has finished is an error: the index $i$ deallocated the moment the sum closed. The same rule applies to integration variables ($\int_a^b f(t)\,dt$) and set-builder descriptions ($\{x \in \R \mid x > 0\}$).

\begin{recoverybox}
\textbf{Pause and think}: Consider the following snippet from a draft proof:
\begin{quote}
``Let $x \in \R$. Since $x^2 \ge 0$, there exists $y \ge 0$ such that $y^2 = x^2$. Thus $y = |x|$. Therefore $y$ is unique for all $x$.''
\end{quote}
Is the variable $y$ in scope on the following line? Why or why not? (The variable $y$ was allocated as a local witness tied to that specific $x$; once the universal claim for $x$ is closed, $y$ cannot be referenced as a global quantity.)
\end{recoverybox}

\subsection{Control flow: exhaustive branch coverage}

When a mathematical proof splits into cases, it is executing an `if-else` or pattern-matching statement. The human compiler checks two structural invariants:
\begin{enumerate}
\item \textbf{Exhaustiveness}: Do the cases cover every possible element of the ambient domain without exception?
\item \textbf{Independence}: Does each branch reach the target conclusion using only the hypotheses active in that specific branch, without leaking local variables into sibling branches?
\end{enumerate}

If your domain is the integers $\Z$ and you consider positive integers ($n > 0$) and negative integers ($n < 0$), you have an unhandled branch: $n = 0$. In programming, an unhandled branch causes an execution crash. In mathematics, it invalidates the proof: a single missing counterexample disproves the theorem.

\subsection{Modular architecture: lemmas as helper functions}

In software design, experienced engineers avoid writing giant monolithic routines. A four-hundred-line function with deeply nested branching is difficult to verify or maintain. Instead, one extracts reusable sub-tasks into clean helper functions: small units that accept an input, enforce a precondition, and return a verified result.

In pure mathematics, \textbf{lemmas serve as helper functions}.

A lemma is a self-contained mathematical result that isolates a specific deduction from the main theorem. Factoring a difficult step into a lemma serves two main functions:
\begin{enumerate}
\item \textbf{Encapsulation}: The technical algebraic computation is contained behind a clear statement.
\item \textbf{Cognitive clarity}: The reader can verify the lemma once, set its details aside, and apply it directly as a trusted step in the main argument.
\end{enumerate}

\begin{example}
Consider the theorem: \emph{For every integer $n$, the expression $n^3 - n$ is divisible by $6$.}

\paragraph{The monolithic approach.}
An author attempts to prove this by expanding $n^3 - n = n(n^2 - 1) = (n-1)n(n+1)$, and then immediately launches into six separate modular arithmetic cases ($n \equiv 0, 1, 2, 3, 4, 5 \pmod 6$) inside the body of the proof. The proof becomes a long sequence of repetitive cases, obscuring why the divisibility holds naturally.

\paragraph{The modular approach with a helper lemma.}
We first extract the core number-theoretic property into a helper lemma:

\begin{lemma}[Consecutive integer divisibility]
For any integer $k$, the product of three consecutive integers $(k-1)k(k+1)$ is divisible by $6$.
\end{lemma}
\begin{proof}
Among any three consecutive integers $k-1, k, k+1$, at least one is a multiple of $2$ (since every second integer is even). In addition, exactly one is a multiple of $3$ (since remainders modulo $3$ cycle regularly through $0, 1, 2$). Because $2$ and $3$ share no common prime factors ($\gcd(2, 3) = 1$), any integer divisible by both $2$ and $3$ is divisible by their product, $6$. Thus $(k-1)k(k+1)$ is divisible by $6$.
\end{proof}

Now the main proof becomes a concise, direct deduction:

\begin{theorem}
For every integer $n$, $n^3 - n$ is divisible by $6$.
\end{theorem}
\begin{proof}
Let $n \in \Z$ be arbitrary. We factor the expression:
\[
n^3 - n = n(n^2 - 1) = (n-1)n(n+1).
\]
Because $n-1, n, n+1$ are three consecutive integers, our lemma applies directly, guaranteeing that their product is divisible by $6$.
\end{proof}

The modular presentation makes the structure transparent (Figure~30.5). The algebraic factorization takes one line, the divisibility logic is isolated in a reusable helper lemma, and the reader's cognitive stack depth never exceeds two frames.
\end{example}

\subsection{Managing cognitive load with orienting signposts}

A human reader cannot scan three pages ahead in working memory to guess why you suddenly introduced an auxiliary polynomial or rearranged an inequality. Brief signposts before a calculation tell the reader what the calculation is for.

Compare these two styles of writing:

\begin{quote}
\textbf{Cryptic style}:
\[
\begin{aligned}
&f(a_1) = f(a_2) \\
&3a_1 + 4 = 3a_2 + 4 \\
&3a_1 = 3a_2 \\
&a_1 = a_2.
\end{aligned}
\]
\end{quote}
This is a naked list of algebraic manipulations. The reader has no idea whether you are proving injectivity, solving for an unknown, or testing a hypothesis.

Now look at the communicative style:

\begin{quote}
\textbf{Communicative style}:
\begin{proof}
We show that $f$ is injective. Let $a_1, a_2 \in \R$ be arbitrary, and assume that $f(a_1) = f(a_2)$. By definition of $f$, this means
\[
3a_1 + 4 = 3a_2 + 4.
\]
Subtracting $4$ from both sides gives $3a_1 = 3a_2$, and dividing by $3$ yields $a_1 = a_2$. Because equal outputs force equal inputs, $f$ is injective.
\end{proof}
\end{quote}

The second version takes only two additional sentences, but it provides complete orientation:
\begin{itemize}
\item It states the \textbf{goal} upfront (``We show that $f$ is injective'').
\item It explicitly \textbf{allocates variables} with their roles (``Let $a_1, a_2 \in \R$ be arbitrary'').
\item It signals the \textbf{antecedent} (``assume that $f(a_1) = f(a_2)$'').
\item It explicitly announces when the \textbf{postcondition} has been satisfied (``Because equal outputs force equal inputs, $f$ is injective'').
\end{itemize}

Every well-crafted mathematical proof relies on three kinds of signposts:
\begin{itemize}
\item \textbf{Goal declarations}: State the claim before beginning the argument (``We claim that $A \subseteq B$'', ``It suffices to show that $|x - y| < \eps$'').
\item \textbf{Structural transitions}: Tell the reader when you are switching modes or entering a sub-routine (``To show uniqueness, assume two such elements exist'', ``Conversely, suppose $x \in B$'').
\item \textbf{Exit certificates}: Tell the reader when an assumption is discharged and what permanent fact was gained (``Since $a_1 = a_2$, this completes the proof of injectivity'').
\end{itemize}

\begin{labbox}
Take any proof you have written previously. Print it out and annotate it with a colored pen:
\begin{itemize}
\item Draw a box around every variable introduction and label its scope lifetime.
\item Highlight every orienting signpost in green.
\item If you find an algebraic line with no explanation of where it came from or where it is going, rewrite it to guide your human reader.
\item Look for any calculation longer than four lines and ask: could this be factored into a clean helper lemma?
\end{itemize}
\end{labbox}

\begin{historybox}
The discovery that proofs are programs grew out of a foundational debate over mathematical truth. In the early twentieth century, the Dutch mathematician L.E.J. Brouwer founded \emph{intuitionism}---a philosophy asserting that mathematical objects exist only if we have an explicit algorithm to construct them. Brouwer rejected classical non-constructive proofs, which show an object exists merely by demonstrating that its non-existence leads to a contradiction. He even rejected the universal validity of the \emph{Law of the Excluded Middle} ($P \lor \neg P$: the classical axiom that every proposition is either true or false, leaving no middle ground). To Brouwer, claiming that an unknown proposition is either true or false without a method to decide which holds is empty symbolism. David Hilbert strongly disagreed, declaring that denying the mathematician the law of excluded middle was like ``denying the astronomer the telescope or the boxer the use of his fists.'' Hilbert insisted that consistent axiomatic symbol manipulation was sufficient foundation for truth.

Classical logic predominated in twentieth-century textbook mathematics, but constructive logic found direct practical applications with the rise of computer science. In the 1970s, Swedish philosopher and logician Per Martin-L\"of introduced \emph{intuitionistic type theory}, a framework uniting logic and computation: types represent mathematical claims, and functional programs represent their constructive proofs. This theoretical bridge led to the development of modern \emph{interactive theorem provers}---software systems like Coq, Isabelle/HOL, and Lean that mechanically verify every logical deduction from foundational axioms. In 2005, Georges Gonthier used Coq to produce the first fully machine-verified proof of the \emph{Four Color Theorem} (the assertion that any planar map requires at most four colors to ensure no adjacent regions share a color). In 2012, Gonthier verified the 255-page \emph{Feit-Thompson Odd Order Theorem}, a landmark theorem in abstract algebra establishing that every finite group of odd order can be decomposed into solvable pieces. In 2021, Fields Medalist Peter Scholze challenged the Lean community to verify his and Dustin Clausen's foundational results in \emph{condensed mathematics} (a modern framework rebuilding topology using algebraic tools to avoid analytical breakdowns). The resulting \emph{Liquid Tensor Experiment} showed that interactive proof assistants can verify subtle proofs at the cutting edge of research.

Yet the \emph{de Bruijn factor} remains an ongoing challenge: translating one page of human textbook mathematics currently requires weeks of expert effort and hundreds of lines of tactic code. Researchers are actively investigating whether automated reasoning and machine learning can auto-formalize informal mathematics without human intervention.
\end{historybox}

\subsection{Proofs for human readers}

Thinking about variable scope, type signatures, and modular lemmas makes proofs easier both to check and to read. Introducing every variable before it is used, closing sub-arguments cleanly, and adding short signposts keep the reader oriented from hypothesis to conclusion.

Formal assistants like Lean verify correctness, but human communication conveys insight: a good proof shows not just that a theorem holds, but why.

With the mechanics of logic, definitions, and proof architecture in place, Chapter~31 (\emph{Second Pass: Set Algebra and Boolean Thinking}) examines the algebra of sets, connecting Boolean operations to Claude Shannon's insight on switching circuits.

\subsection{Exercises}

\begin{enumerate}
  \item \textbf{Mental Check: Identifying Scope Leakage.}
  Examine the following excerpt from a student's attempt to prove that $x^2 \ge 0$ for all real numbers $x$:
  \begin{quote}
  ``Case 1 ($x \ge 0$): We write $x = a$ with $a \ge 0$. Then $x^2 = a^2 \ge 0$.\\
  Case 2 ($x < 0$): We write $x = -b$ with $b > 0$. Then $x^2 = (-b)^2 = b^2 > 0$.\\
  In either case $x^2 \ge 0$. Also, equating the expressions gives $a^2 = b^2$, so $a = b$, which means $x = -x$, so $x = 0$.''
  \end{quote}
  Where does the lexical scope violation occur? Why is it invalid to equate $a$ and $b$?

  \item \textbf{Mental Check: Catching Unhandled Branches.}
  A student attempts to prove that for all $x \in \R$, the expression $f(x) = x / |x|$ satisfies $f(x)^2 = 1$. The proof reads:
  \begin{quote}
  ``Case 1 ($x > 0$): Then $|x| = x$, so $f(x) = x/x = 1$, and $1^2 = 1$.\\
  Case 2 ($x < 0$): Then $|x| = -x$, so $f(x) = x/(-x) = -1$, and $(-1)^2 = 1$.\\
  Therefore $f(x)^2 = 1$ for all real numbers $x$.''
  \end{quote}
  Identify the unhandled branch in this argument. What does this reveal about the domain of $f$?

  \item \textbf{Refactoring Monolithic Calculations into Helper Lemmas.}
  Consider the theorem: ``For all integers $n$, $n^5 - n$ is divisible by $30$.''
  Notice that $30 = 2 \times 3 \times 5$, and that $n^5 - n$ factors as $n(n-1)(n+1)(n^2+1)$.
  \begin{enumerate}[label=(\alph*)]
    \item Formulate a helper lemma stating that $(n-1)n(n+1)$ is divisible by $6$ for any integer $n$, and give a short, self-contained proof.
    \item Formulate a second helper lemma stating that $n(n-1)(n+1)(n^2+1)$ is divisible by $5$ for any integer $n$. (Hint: Write $n^2 + 1 = (n^2 - 4) + 5 = (n-2)(n+2) + 5$ to produce five consecutive integers.)
    \item Using your two helper lemmas, write a clean, three-sentence proof of the main theorem. Explain how this refactoring reduces the reader's cognitive load.
  \end{enumerate}

  \item \textbf{The Curry-Howard Translation.}
  For each of the following propositional formulas, write the corresponding functional programming type signature, and describe in one plain sentence the computational task that a proof must perform:
  \begin{enumerate}[label=(\alph*)]
    \item $P \land Q \implies P$ (Conjunction elimination).
    \item $(P \implies Q) \land (Q \implies R) \implies (P \implies R)$ (Transitivity of implication).
    \item $P \implies (Q \implies P)$ (Weakening).
  \end{enumerate}

  \item \textbf{Tracing Scope in a Surjection Proof.}
  Recall that a function $f: X \to Y$ is surjective if for every $y \in Y$, there exists $x \in X$ such that $f(x) = y$.
  \begin{enumerate}[label=(\alph*)]
    \item Write a communicative proof that if $f: A \to B$ and $g: B \to C$ are both surjective, then the composite function $g \circ f: A \to C$ is surjective.
    \item Alongside your proof, trace the compiler stack: list which variable is introduced at the start, when the witnesses in $B$ and $A$ are allocated, and at what exact line the local scope frame is discharged to export the universal result.
  \end{enumerate}

  \item \textbf{Constructive versus Classical Existence.}
  Consider the theorem: ``There exist irrational numbers $a, b \in \R \setminus \Q$ such that $a^b$ is rational.''
  \begin{enumerate}[label=(\alph*)]
    \item The standard classical proof considers the number $\sqrt{2}^{\sqrt{2}}$. If $\sqrt{2}^{\sqrt{2}}$ is rational, we choose $a = b = \sqrt{2}$. If $\sqrt{2}^{\sqrt{2}}$ is irrational, we choose $a = \sqrt{2}^{\sqrt{2}}$ and $b = \sqrt{2}$, yielding $a^b = (\sqrt{2}^{\sqrt{2}})^{\sqrt{2}} = \sqrt{2}^2 = 2 \in \Q$. Explain why this proof does not provide an executable witness under the Curry-Howard correspondence.
    \item Provide a fully constructive proof by choosing $a = \sqrt{2}$ and $b = \log_2(9)$. Verify that $a$ is irrational, prove that $b$ is irrational by showing that $2^{p/q} = 9$ contradicts unique prime factorization, and compute $a^b$ directly to verify it is an integer.
  \end{enumerate}
\end{enumerate}
