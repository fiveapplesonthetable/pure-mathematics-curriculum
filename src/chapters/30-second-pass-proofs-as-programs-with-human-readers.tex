\subsection{The Curry-Howard breakthrough: proofs as executable code}

In Chapter~29 (\emph{Second Pass: Definitions Under a Microscope}), we examined mathematical definitions as precise input/output contracts. We learned to ask: what preconditions must an object meet to qualify, and what guaranteed properties does that classification provide downstream?

Yet having a collection of definitions is only a starting point. Mathematics proceeds by chaining those contracts together to transform initial premises into a conclusion. We call that deductive sequence a \textbf{proof}.

For centuries, mathematicians viewed proofs primarily through the lens of rhetoric: a proof was an argument written to convince a reader. In the twentieth century, logicians found a precise link: \textbf{a proof corresponds to a program that can be run}.

In 1934, the American logician Haskell Curry noticed an unexpected correspondence: the formal deduction rules of \emph{intuitionistic logic}---a framework of logic where claiming an object exists requires providing an explicit algorithm to construct it---mirrored the type signatures of functions in \emph{combinatory logic} (a system that computes purely by combining functions without named variables). Thirty-five years later, in 1969, William Alvin Howard formalized Curry's observation into an exact mathematical dictionary: the \textbf{Curry-Howard correspondence}.

Under the Curry-Howard correspondence, logic and computation share the same structure: propositions correspond to data types, and proofs correspond to programs that construct elements of those types. A \emph{data type} is a kind of value a program can handle, such as ``integer'' or ``pair of integers''; an \emph{element} of a type is one value of that kind, such as $7$ or $(3, 5)$. Read a proposition $P$ as the type whose elements are the proofs of $P$: proving $P$ means building one element of that type. For example, a proof of $P \implies Q$ is a function that takes any proof of $P$ as input and returns a proof of $Q$.

Figure~\ref{30:fig-curry-howard} summarizes the dictionary. A \emph{product type} holds pairs: a proof of $P \land Q$ is a pair $(p, q)$ made of a proof $p$ of $P$ and a proof $q$ of $Q$. A \emph{sum type}, also called a \emph{tagged union}, holds one value plus a tag saying which side it came from: a proof of $P \lor Q$ is either a proof of $P$ labelled ``left'' or a proof of $Q$ labelled ``right''. \emph{Modus ponens} is the rule ``from $P$ and $P \implies Q$, conclude $Q$''; in the program view it is \emph{function application}, feeding the proof $p$ of $P$ into the function $f$ that proves $P \implies Q$ to get the proof $f(p)$ of $Q$. The last two entries need more explanation. The notation $\Pi_{(x:A)} P(x)$ names a \emph{dependent function}: a program that accepts any input $x$ of type $A$ and returns evidence for $P(x)$, where the type of the output changes with the input---exactly what a proof of $\forall x \in A, \, P(x)$ does when it handles an arbitrary $x$. A \emph{dependent pair} $(w, \text{evidence})$ packages a specific witness $w \in A$ together with a certificate that $P(w)$ holds---exactly what a proof of $\exists x \in A, \, P(x)$ must hand over.

Figure~\ref{30:fig-proof-machine} draws two of these entries as machines. Modus ponens feeds a proof into a function. And a proof of $P \land Q \implies Q \land P$ is a short program: it takes a pair $(p, q)$ and returns the swapped pair $(q, p)$.

\subsection{The human compiler: managing cognitive stack depth}

Yet mathematical proofs differ from software in one essential respect: \textbf{a proof compiles in the mind of a human reader}.

A compiler (the program that checks and translates source code, as in Chapter~12) has no working-memory limit. A human reader can comfortably track only a few active variables and hypotheses at once. Programmers picture this bookkeeping as a \emph{stack}: a pile where the last item added is the first one removed. When a program enters a function, it \emph{pushes} a \emph{frame} (a record of that function's local variables) onto the stack; when the function returns, it \emph{pops} the frame off and those variables stop existing. Reading a proof works the same way: the reader \emph{allocates} (sets aside memory for) each new variable, pushes an assumption when a sub-proof starts, and pops it when the sub-proof or case ends. If an author introduces multiple undeclared symbols or buries the main line of reasoning in casework, the reader's working memory is quickly overwhelmed. Clear proof writing requires the same discipline as clean code: explicit scope, managed variable lifetimes, and modular structure. Figure~\ref{30:fig-proof-stack} traces this for the proof that a composition of two injective functions is injective.

\subsection{Variable scope: allocation, leakage, and shadowing}

Every time you write ``Let $x \in S$ be arbitrary'' or ``Choose $k \in \Z$ such that $n = 2k$,'' you are allocating a variable name in the reader's working memory. As in a programming language, that variable has a \emph{lexical scope}---a boundary of text outside of which the name no longer exists.

\subsubsection{1. Dangling variables and scope leakage}
A variable cannot be referenced outside the local block in which it was introduced.
Consider a proof by cases:
\begin{quote}
\emph{Flawed reasoning}:\\
``Case 1 ($n$ is even): Then $n = 2k$.\\
Case 2 ($n$ is odd): Then $n = 2m + 1$.\\
Therefore $n(n+1) = 2k(2m+1) \dots$''
\end{quote}
The variable $k$ was defined strictly inside Case~1, and $m$ was defined strictly inside Case~2. In any single evaluation of the proof, either $n$ is even or $n$ is odd; the two branches never run at the same time. Multiplying $2k$ by $2m+1$ is a scope violation: as Figure~\ref{30:fig-scope-leak} shows, the author uses variables from two branches that never hold at the same time.

\subsubsection{2. Shadowing and premature binding}
If your theorem already contains a fixed parameter $c$, never write:
\begin{quote}
``Let $c$ be an arbitrary element of $S$.''
\end{quote}
Re-using the letter $c$ \emph{shadows} the original parameter: the new $c$ hides the old one, and the reader can no longer tell which $c$ a later line means. Introduce a fresh symbol instead: ``Let $x \in S$ be arbitrary.'' Figure~\ref{30:fig-shadowing} shows the two versions side by side.

\subsubsection{3. Bound versus free variables}
Some variables persist across sentences; others live only inside one expression (Chapter~3 introduced free and bound variables). Take the summation
\[
\sum_{i=1}^{n} i = \frac{n(n+1)}{2}.
\]
The upper limit $n$ is a \textbf{free variable} (it determines the value of the sum and exists before and after the calculation). The index $i$ is a \textbf{bound variable} (a dummy index local to the summation operator). Writing ``Because $i \le n$, we deduce...'' after the sum has finished is an error: the index $i$ stopped existing the moment the sum closed. Figure~\ref{30:fig-bound-free} draws the two lifetimes. The same rule applies to integration variables ($\int_a^b f(t)\,dt$) and set-builder descriptions ($\{x \in \R \mid x > 0\}$).

\begin{recoverybox}
\textbf{Pause and think}: Consider the following snippet from a draft proof:
\begin{quote}
``Let $x \in \R$ be arbitrary. Since $x^2 \ge 0$, there exists $y \ge 0$ such that $y^2 = x^2$, and then $y = |x|$. This shows that $|x|^2 = x^2$ for every $x \in \R$. Finally, since $y \ge 0$, the number $y + 1$ is positive.''
\end{quote}
Is the variable $y$ in scope in the final sentence? Why or why not? (No. The variable $y$ was allocated as a local witness tied to one specific $x$, inside the argument for an arbitrary $x$. Once the sentence ``for every $x \in \R$'' closes that argument, $x$ and $y$ are both deallocated: there is now a different $y$ for every $x$, so ``the number $y + 1$'' refers to nothing in particular.)
\end{recoverybox}

\subsection{Control flow: exhaustive branch coverage}

When a mathematical proof splits into cases, it behaves like an \texttt{if-else} statement in a program, which runs one branch or another depending on its input. The reader checks two conditions:
\begin{enumerate}
\item \textbf{Exhaustiveness}: Do the cases cover every possible element of the set the variable ranges over, without exception?
\item \textbf{Independence}: Does each branch reach the target conclusion using only the hypotheses active in that specific branch, without leaking local variables into sibling branches?
\end{enumerate}

If your variable ranges over the integers $\Z$ and you consider positive integers ($n > 0$) and negative integers ($n < 0$), you have an unhandled branch: $n = 0$. In programming, an unhandled branch can crash the program. In mathematics, it leaves the proof incomplete: nothing has been shown about $n = 0$, and if the claim happens to fail at $n = 0$, the theorem is false. Figure~\ref{30:fig-case-coverage} compares a case split with a gap and one without.

\subsection{Modular architecture: lemmas as helper functions}

In software design, experienced engineers avoid writing giant \emph{monolithic} routines (one huge block of code that does everything). A four-hundred-line function with deeply nested branching is difficult to verify or maintain. Instead, one extracts reusable sub-tasks into clean helper functions: small units that accept an input, require a precondition (a condition the input must meet), and return a verified result.

In pure mathematics, \textbf{lemmas serve as helper functions}.

A lemma is a self-contained mathematical result that isolates a specific deduction from the main theorem. Factoring a difficult step into a lemma serves two main functions:
\begin{enumerate}
\item \textbf{Encapsulation}: The technical algebraic computation is contained behind a clear statement.
\item \textbf{Cognitive clarity}: The reader can verify the lemma once, set its details aside, and apply it directly as a trusted step in the main argument.
\end{enumerate}

\begin{example}
Consider the theorem: \emph{For every integer $n$, the expression $n^3 - n$ is divisible by $6$.}

\paragraph{The monolithic approach.}
An author attempts to prove this by expanding $n^3 - n = n(n^2 - 1) = (n-1)n(n+1)$, and then immediately launches into six separate modular arithmetic cases ($n \equiv 0, 1, 2, 3, 4, 5 \pmod 6$) inside the body of the proof. The proof becomes a long sequence of repetitive cases, which hides the reason the divisibility holds.

\paragraph{The modular approach with a helper lemma.}
We first move the key fact about divisibility into a helper lemma:

\begin{lemma}[Consecutive integer divisibility]
For any integer $k$, the product of three consecutive integers $(k-1)k(k+1)$ is divisible by $6$.
\end{lemma}
\begin{proof}
Among any three consecutive integers $k-1, k, k+1$, at least one is a multiple of $2$ (since every second integer is even). In addition, exactly one is a multiple of $3$ (since remainders modulo $3$ cycle regularly through $0, 1, 2$); Figure~\ref{30:fig-consecutive} shows this on the number line. So the product $m = (k-1)k(k+1)$ is divisible by both $2$ and $3$: write $m = 2a$ and $m = 3b$ for integers $a, b$. Because $2$ and $3$ share no common factor, we can combine them through the identity $1 = 3 - 2$:
\begin{align*}
m &= 3m - 2m \\
  &= 3(2a) - 2(3b) && \text{(substitute $m = 2a$ and $m = 3b$)} \\
  &= 6(a - b).
\end{align*}
Thus $(k-1)k(k+1)$ is divisible by $6$.
\end{proof}

Now the main proof is short:

\begin{theorem}
For every integer $n$, $n^3 - n$ is divisible by $6$.
\end{theorem}
\begin{proof}
Let $n \in \Z$ be arbitrary. We factor the expression:
\begin{align*}
n^3 - n &= n(n^2 - 1) \\
        &= (n-1)n(n+1).
\end{align*}
Because $n-1, n, n+1$ are three consecutive integers, our lemma applies directly, guaranteeing that their product is divisible by $6$.
\end{proof}

The modular presentation makes the structure easy to see (Figure~\ref{30:fig-lemma-architecture}). The algebraic factorization takes one line, the divisibility logic is isolated in a reusable helper lemma, and the reader's cognitive stack depth never exceeds two frames.
\end{example}

\subsection{Managing cognitive load with orienting signposts}

A human reader cannot scan three pages ahead in working memory to guess why you suddenly introduced an auxiliary polynomial or rearranged an inequality. Brief signposts before a calculation tell the reader what the calculation is for.

Take the function $f\colon \R \to \R$ given by $f(x) = 3x + 4$, and compare these two ways of writing the same argument:

\begin{quote}
\textbf{Cryptic style}:
\[
\begin{aligned}
&f(a_1) = f(a_2) \\
&3a_1 + 4 = 3a_2 + 4 \\
&3a_1 = 3a_2 \\
&a_1 = a_2.
\end{aligned}
\]
\end{quote}
This is a naked list of algebraic manipulations. The reader has no idea whether you are proving injectivity, solving for an unknown, or testing a hypothesis.

Now look at the communicative style:

\begin{quote}
\textbf{Communicative style}:
\begin{proof}
We show that $f$ is injective. Let $a_1, a_2 \in \R$ be arbitrary, and assume that $f(a_1) = f(a_2)$. By definition of $f$, this means
\[
3a_1 + 4 = 3a_2 + 4.
\]
Subtracting $4$ from both sides gives $3a_1 = 3a_2$, and dividing by $3$ yields $a_1 = a_2$. Because equal outputs force equal inputs, $f$ is injective.
\end{proof}
\end{quote}

The second version adds two sentences, and they tell the reader everything needed to follow along (Figure~\ref{30:fig-signposts} labels each sentence by its job):
\begin{itemize}
\item It states the \textbf{goal} upfront (``We show that $f$ is injective'').
\item It explicitly \textbf{allocates variables} with their roles (``Let $a_1, a_2 \in \R$ be arbitrary'').
\item It signals the \textbf{antecedent}, the ``if'' part being assumed (``assume that $f(a_1) = f(a_2)$'').
\item It announces when the \textbf{postcondition} (the promised result) has been reached (``Because equal outputs force equal inputs, $f$ is injective'').
\end{itemize}

Good proofs use three kinds of signposts:
\begin{itemize}
\item \textbf{Goal declarations}: State the claim before beginning the argument (``We claim that $A \subseteq B$'', ``It suffices to show that $|x - y| < \eps$'').
\item \textbf{Structural transitions}: Tell the reader when you are switching modes or starting a sub-argument (``To show uniqueness, assume two such elements exist'', ``Conversely, suppose $x \in B$'').
\item \textbf{Exit certificates}: Tell the reader when an assumption is discharged and what permanent fact was gained (``Since $a_1 = a_2$, this completes the proof of injectivity'').
\end{itemize}

Take any proof you have written previously. Print it out and annotate it with a colored pen:
\begin{itemize}
\item Draw a box around every variable introduction and label its scope lifetime.
\item Highlight every orienting signpost in green.
\item If you find an algebraic line with no explanation of where it came from or where it is going, rewrite it to guide your human reader.
\item Look for any calculation longer than four lines and ask: could this be factored into a clean helper lemma?
\end{itemize}
\end{labbox}

\begin{historybox}
The discovery that proofs are programs grew out of a foundational debate over mathematical truth. Chapter~5 told how L.E.J. Brouwer's \emph{intuitionism} (an object exists only if we have an explicit method to construct it) rejected the Law of the Excluded Middle $P \lor \neg P$ for infinite sets, and how David Hilbert objected.

Classical logic predominated in twentieth-century textbook mathematics, but constructive logic found direct practical applications with the rise of computer science. In the 1970s, Swedish philosopher and logician Per Martin-L\"of introduced \emph{intuitionistic type theory}, a framework uniting logic and computation: types represent mathematical claims, and functional programs represent their constructive proofs. This theoretical bridge led to the development of modern \emph{interactive theorem provers}---software systems like Coq, Isabelle/HOL, and Lean that mechanically verify every logical deduction from foundational axioms. In 2005, Georges Gonthier used Coq to produce the first fully machine-verified proof of the \emph{Four Color Theorem} (the assertion that any planar map requires at most four colors to ensure no adjacent regions share a color). In 2012, Gonthier verified the 255-page \emph{Feit-Thompson Odd Order Theorem}, a landmark result in abstract algebra stating that every finite group with an odd number of elements is \emph{solvable} (it can be taken apart step by step into commutative pieces, in the sense of Chapter~21). At the end of 2020, Fields Medalist Peter Scholze challenged the Lean community to verify a key theorem from his and Dustin Clausen's work on \emph{condensed mathematics} (a new framework designed so that algebraic methods work smoothly on spaces that carry a topology). The resulting \emph{Liquid Tensor Experiment}, completed in 2022, showed that interactive proof assistants can verify subtle proofs at the cutting edge of research.

The cost of formalization remains a challenge. The \emph{de Bruijn factor}, named after the Dutch mathematician Nicolaas de Bruijn, measures how many times longer a fully formal proof is than the written proof it checks. Translating one page of textbook mathematics can take weeks of expert effort and hundreds of lines of \emph{tactic code} (commands that tell the proof assistant which proof step to try next). Researchers are actively investigating whether automated reasoning and machine learning can auto-formalize informal mathematics without human intervention.
\end{historybox}

\subsection{Proofs for human readers}

Thinking about variable scope, type signatures, and modular lemmas makes proofs easier both to check and to read. Introducing every variable before it is used, closing sub-arguments cleanly, and adding short signposts keep the reader oriented from hypothesis to conclusion.

Proof assistants like Lean check that each step is correct. A proof written for people should also show why the theorem holds.

With the mechanics of logic, definitions, and proof architecture in place, Chapter~31 (\emph{Second Pass: Set Algebra and Boolean Thinking}) examines the algebra of sets and its link to Claude Shannon's work on electrical switching circuits.

\subsection{Exercises}

\begin{enumerate}
  \item \textbf{Mental Check: Identifying Scope Leakage.}
  Examine the following excerpt from a student's attempt to prove that $x^2 \ge 0$ for all real numbers $x$:
  \begin{quote}
  ``Case 1 ($x \ge 0$): We write $x = a$ with $a \ge 0$. Then $x^2 = a^2 \ge 0$.\\
  Case 2 ($x < 0$): We write $x = -b$ with $b > 0$. Then $x^2 = (-b)^2 = b^2 > 0$.\\
  In either case $x^2 \ge 0$. Also, equating the expressions gives $a^2 = b^2$, so $a = b$, which means $x = -x$, so $x = 0$.''
  \end{quote}
  Where does the lexical scope violation occur? Why is it invalid to equate $a$ and $b$?

  \item \textbf{Mental Check: Catching Unhandled Branches.}
  A student attempts to prove that for all $x \in \R$, the expression $f(x) = x / \lvert x \rvert$ satisfies $f(x)^2 = 1$. The proof reads:
  \begin{quote}
  ``Case 1 ($x > 0$): Then $|x| = x$, so $f(x) = x/x = 1$, and $1^2 = 1$.\\
  Case 2 ($x < 0$): Then $|x| = -x$, so $f(x) = x/(-x) = -1$, and $(-1)^2 = 1$.\\
  Therefore $f(x)^2 = 1$ for all real numbers $x$.''
  \end{quote}
  Identify the unhandled branch in this argument. What does this reveal about the domain of $f$?

  \item \textbf{Refactoring Monolithic Calculations into Helper Lemmas.}
  Consider the theorem: ``For all integers $n$, $n^5 - n$ is divisible by $30$.''
  Note that $30 = 2 \times 3 \times 5$, and that $n^5 - n$ factors as $n(n-1)(n+1)(n^2+1)$.
  \begin{enumerate}[label=(\alph*)]
    \item Formulate a helper lemma stating that $(n-1)n(n+1)$ is divisible by $6$ for any integer $n$, and give a short, self-contained proof.
    \item Formulate a second helper lemma stating that $n(n-1)(n+1)(n^2+1)$ is divisible by $5$ for any integer $n$. (Hint: Write $n^2 + 1 = (n^2 - 4) + 5 = (n-2)(n+2) + 5$ to produce five consecutive integers.)
    \item Using your two helper lemmas, write a clean, three-sentence proof of the main theorem. Explain how this refactoring reduces the reader's cognitive load. Hint: if $m = 6a$ and $m = 5b$, then
    \[
    m = 6m - 5m = 6(5b) - 5(6a) = 30(b - a).
    \]
  \end{enumerate}

  \item \textbf{The Curry-Howard Translation.}
  For each of the following propositional formulas, write the corresponding functional programming type signature (writing $P \times Q$ for the type of pairs $(p, q)$ that proves $P \land Q$, and $P \to Q$ for the type of functions that proves $P \implies Q$), and describe in one plain sentence the computational task that a proof must perform:
  \begin{enumerate}[label=(\alph*)]
    \item $P \land Q \implies P$ (Conjunction elimination).
    \item $(P \implies Q) \land (Q \implies R) \implies (P \implies R)$ (Transitivity of implication).
    \item $P \implies (Q \implies P)$ (Weakening).
  \end{enumerate}

  \item \textbf{Tracing Scope in a Surjection Proof.}
  Recall that a function $f\colon X \to Y$ is surjective if for every $y \in Y$, there exists $x \in X$ such that $f(x) = y$.
  \begin{enumerate}[label=(\alph*)]
    \item Write a communicative proof that if $f\colon A \to B$ and $g\colon B \to C$ are both surjective, then the composite function $g \circ f\colon A \to C$ is surjective.
    \item Alongside your proof, trace the compiler stack: list which variable is introduced at the start, when the witnesses in $B$ and $A$ are allocated, and at what exact line the local scope frame is discharged to export the universal result.
  \end{enumerate}

  \item \textbf{Constructive versus Classical Existence.}
  Consider the theorem: ``There exist irrational numbers $a, b \in \R \setminus \Q$ such that $a^b$ is rational.''
  \begin{enumerate}[label=(\alph*)]
    \item The standard classical proof considers the number $\sqrt{2}^{\sqrt{2}}$. If $\sqrt{2}^{\sqrt{2}}$ is rational, we choose $a = b = \sqrt{2}$. If $\sqrt{2}^{\sqrt{2}}$ is irrational, we choose $a = \sqrt{2}^{\sqrt{2}}$ and $b = \sqrt{2}$, yielding
    \[
    a^b = \bigl(\sqrt{2}^{\sqrt{2}}\bigr)^{\sqrt{2}} = \sqrt{2}^{\sqrt{2} \cdot \sqrt{2}} = \sqrt{2}^{2} = 2 \in \Q.
    \]
    Explain why this proof does not provide an executable witness under the Curry-Howard correspondence.
    \item Provide a fully constructive proof by choosing $a = \sqrt{2}$ and $b = \log_2(9)$. Verify that $a$ is irrational, prove that $b$ is irrational by showing that $2^{p/q} = 9$ contradicts unique prime factorization, and compute $a^b$ directly to verify it is an integer.
  \end{enumerate}
\end{enumerate}
